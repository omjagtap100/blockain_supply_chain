    What is this DApp?
    A blockchain-based shipment tracker built on Ethereum. Each shipment step (e.g., Warehouse → Transit → Delivered) is stored as an immutable on-chain record, giving all parties a tamper-proof audit trail.

    Extended from Task 6.2C (Priority Todo DApp) with three HD feature pillars: security hardening, privacy controls, and scalability improvements.
    Security — Ownable Pattern
    The contract implements an Ownable access control pattern:

    • Only the deployer (owner) can deleteTask or updatePriority.
    • Only the owner or the assigned party can toggleCompleted.
    • Ownership can be transferred via transferOwnership().

    This prevents any anonymous address from tampering with shipment records.

    Security scan: Run slither contracts/TodoList.sol to verify no re-entrancy, integer overflow, or unprotected self-destruct vulnerabilities.
    Privacy — Assignee & Content Hash
    Each task can be assigned to a specific Ethereum address (assignee).

    • getTasksByAssignee(addr) returns task IDs only to the assignee or owner — no data leakage to third parties.
    • contentHash (bytes32) stores a keccak256 hash of the full off-chain content (IPFS CID). The blockchain never stores raw sensitive data — only a verifiable fingerprint.

    How to use: Enter an assignee wallet address when creating a task. Only that address (and the owner) will see filtered task queries.
    Scalability — Indexed Events & Batch Query
    Two scalability improvements over the base DApp:

    1. Indexed events — TaskCreated, TaskCompleted, etc. use indexed parameters on id, priority, and assignee. This allows Ethereum nodes to filter logs in O(1) instead of scanning all events.

    2. Batch query — getActiveTaskIds() returns all live task IDs in a single JSON-RPC call, reducing front-end round-trips from N calls to 1 + N (one batch + individual task reads).

    Supply Chain Context
    In a supply chain scenario each task represents a logistics step:

    • Priority High → Time-sensitive cold-chain delivery
    • Priority Medium → Standard parcel transit
    • Priority Low → Bulk non-urgent stock

    The assignee field maps to the logistics party responsible (e.g., freight forwarder's wallet). The deadline encodes the expected delivery timestamp on-chain, creating an immutable SLA record.

    Blockchain provides transparency (all parties see the same ledger), immutability (records cannot be falsified), and auditability (full event history via indexed logs).
