PART 3 — MANUAL REVIEW (business logic Slither cannot check)
-------------------------------------------------------------------------------

Slither checks generic patterns, it does not know which address is
supposed to be allowed to call which function. That has to be checked by
hand against the contract's own rules.

[PASS] Access control
  - deleteTask(), updatePriority(), updateAssignee(), transferOwnership():
    all guarded by onlyOwner. Confirmed both by reading the modifier and by
    the "non-owner cannot ..." tests in test/TodoList.test.js.
  - toggleCompleted(): guarded by
    require(msg.sender == owner || msg.sender == tasks[_id].assignee).
    Confirmed by the "assignee can toggle their own task" and "non-assignee
    non-owner cannot toggle task" tests.
  - getTasksByAssignee(): guarded by
    require(msg.sender == owner || msg.sender == _assignee).
    Confirmed by the "non-owner non-assignee cannot query" test.
  - transferOwnership() also checks _newOwner != address(0), so ownership
    cannot be accidentally burned.

[PASS] Reentrancy
  - Every state-changing function follows checks-effects-interactions.
  - No external calls anywhere in the contract, no ETH is ever sent.

[PASS] Integer overflow / underflow
  - taskCount only ever increments by 1 (taskCount++), bounded by uint256.
  - priority is validated with require(_priority >= 1 && _priority <= 3).
  - No subtraction or multiplication on user-supplied values.

[PASS] Denial of service
  - getActiveTaskIds() loops over taskCount. For a local Ganache demo with
    a small number of shipments this is fine. At large scale (thousands of
    tasks) this loop would raise gas cost, noted as future work in the
    report, not a vulnerability an attacker can trigger for free since the
    caller pays their own gas.

[INFO] Timestamp dependence
  - deadline is a plain user-supplied uint used only for display in the UI.
    No business logic branches on block.timestamp.

PART 4 — MANUAL PENETRATION TEST, FRONT END (src/app.js, src/index.html)
-------------------------------------------------------------------------------

[FOUND & FIXED] Stored XSS via task content
  - src/app.js line 115 originally rendered task descriptions with jQuery's
    .html(content), which does not escape HTML. A task created with content
    like <img src=x onerror=alert(1)> would execute script in the browser
    of anyone viewing the task list.
  - Fix applied: changed to .text(content), which renders the string as
    plain text. Verified by re-reading the file after the change.
  - Impact before fix: Medium (requires a wallet able to call createTask,
    but the payload would then run in every other viewer's browser,
    including the owner's).

[PASS] CSRF
  - No session cookies or server-side authentication. Every write requires
    an explicit MetaMask signature, so a forged cross-site request cannot
    submit a transaction on the user's behalf without their wallet approval.

[PASS] Replay attack
  - Transaction nonces are managed by MetaMask / the Ethereum client.
    A captured signed transaction cannot be replayed once mined.

[INFO] Transport security
  - The app is served over http://localhost during local development.
    A production deployment should be served over HTTPS and should verify
    the RPC endpoint it connects to, to prevent a man-in-the-middle from
    swapping in a malicious provider.
